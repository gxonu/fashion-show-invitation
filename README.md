원본의 공개 HTML·CSS·JavaScript와 이미지로 화면을 동일하게 재현한 정적 웹사이트입니다.
현재 원본 행사명·일정·작품 설명·이미지는 그대로이며, 원본 참석자 명단은 가져오지 않았습니다.
실제 명단 대신 가상 테스트 데이터만 들어 있습니다. 코드는 공개 저장소로 관리하며, 원본 디자인과 가상 데이터의 미리보기를 GitHub Pages에 배포합니다.

## 공개 버전과 개발 버전 관리

| Git 기준 | 용도 |
| --- | --- |
| `main` | 현재 공개 버전의 소스와 검토가 완료된 변경 |
| `develop` | UI/UX 개선 및 클라이언트 추가 요청 개발 |
| `gh-pages` | 실제 GitHub Pages가 제공하는 빌드 파일 |
| `client-baseline-2026-10-10` | 개발 분리 시점의 소스 보존 태그 |

현재 공개 배포 기준 커밋은 `gh-pages`의 `881fa956ea8ab0bf07f0c5a190cebf738ec275c6`입니다.
`main` 또는 `develop`에 커밋·푸시해도 사이트가 자동 변경되지 않습니다. 각 버전은 아래 명령으로 따로 배포합니다.

- 클라이언트 공개 버전: https://gxonu.github.io/fashion-show-invitation/spectrum/
- 개발 미리보기: https://gxonu.github.io/fashion-show-invitation/develop/spectrum/

`develop`에서 개발 미리보기를 갱신합니다. 현재 전체 명단과 테스트 번호를 함께 사용하며, `--preview`는 `gh-pages`의 `develop/` 경로만 변경합니다.

```bash
python3 scripts/deploy_pages.py --preview --roster private/rosters/lookup.json --include-demo
```

개발은 `git switch develop` 후 진행합니다. 기존 로컬 미리보기에서 확인하고 변경을 `develop`에 커밋·푸시합니다. 클라이언트가 확인한 변경만 PR로 `main`에 병합한 다음, 공개 반영 요청이 있을 때 `main`에서 아래 명령을 실행합니다.

```bash
python3 scripts/deploy_pages.py --roster private/rosters/lookup.json --include-demo
```

공개 버전 배포는 `main`에서만, `--preview` 배포는 `develop`에서만 실행할 수 있습니다. 공개 버전을 배포해도 개발 미리보기 경로는 유지됩니다. 엑셀·PDF 원본 대신 변환된 조회 데이터만 배포하며, `private/` 자료는 소스 브랜치에 포함하지 않습니다. 행사 운영 배포에서는 테스트 번호를 제외하려면 `--include-demo`를 생략합니다.
피그마의 문구·행사 내용은 임의로 변경하지 않으며, 새 디자인 개선은 `develop`에서 관리합니다.

### 2026-10-16 개발 버전 갱신

- 좌석 조회 원본은 `private/rosters/지정좌석_2026-10-16.xlsx`입니다. 기존 별도 VIP 2명을 유지하며, 일반 지정석 157명·VIP 18명, 총 175개 번호입니다. 이전 명단에서 7개 번호가 추가됐으며 기존 번호의 배정은 동일합니다. 전화번호가 없는 43행은 조회 데이터에서 제외합니다.
- 업데이트할 때는 아래처럼 원본 파일을 명시합니다. 엑셀·별도 VIP 원본은 Git과 배포에 포함하지 않습니다.

```bash
python3 scripts/prepare_spectrum_roster.py private/rosters/지정좌석_2026-10-16.xlsx
python3 scripts/deploy_pages.py --preview --roster private/rosters/lookup.json --include-demo
SPECTRUM_URL=http://127.0.0.1:4175/spectrum/ SPECTRUM_ROSTER=private/rosters/지정좌석_2026-10-16.xlsx node tests/real-roster.browser.cjs
```

- 모바일 이미지는 원본 PNG를 보존하고 WebP를 제공합니다. 쇼 소개 이미지는 표시 폭 342px의 3배인 1026px, 품질 90으로 변환했습니다. 약도와 메인 그림 두 장은 무손실 변환하여 픽셀이 동일합니다. 전시 이미지는 원본이 더 작아 PNG를 유지합니다.
- 변환된 4개 이미지의 합계는 약 8.62MB에서 0.78MB로 감소했습니다. `python3 scripts/optimize_spectrum_images.py`로 재생성할 수 있으며, 일반 빌드에는 추가 도구가 필요하지 않습니다.
- 같은 날 Figma 최신 화면을 확인했습니다. 메인 시간은 16:00–18:00, 전시·입장 시간은 16:00–17:00으로 변경됐고 타임라인의 리허설 항목이 삭제됐습니다. 전시 제목·디자이너 소개·좌석/입장 안내 문구도 변경됐습니다. 이 Figma 변경은 현재 확인 단계이며 이번 이미지 최적화에 문구 변경은 포함하지 않습니다.

## 실행

Python 3만 필요하며 npm 설치나 프레임워크 빌드는 필요하지 않습니다.

### Mac 로컬 개발

2026-10-09부터 아래 로컬 폴더에서 개발을 이어갑니다. 기존 SSH 서버 접속이나 포트 포워딩은 필요하지 않습니다.

```bash
cd "/Users/geonu/Desktop/인하대 인공지능 공학과/04_대외활동/2026/2026_fashion-show-invitation"
python3 scripts/build.py
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist
```

기존 초대장: http://localhost:4173/ · 새 디자인 목업: http://localhost:4173/mockup/

서버 종료는 터미널에서 `Ctrl+C`를 누릅니다.
HTML 파일을 직접 더블클릭하면 CSV 조회가 브라우저 보안 정책으로 작동하지 않을 수 있습니다.
원본 파일 수정 후에는 별도 터미널에서 `python3 scripts/build.py`를 다시 실행하고 브라우저를 새로고침하세요.

### SSH 원격 서버에서 실행하는 경우

서버의 저장소 폴더에서 위 빌드·실행 명령을 수행하고, 개인 PC의 별도 터미널에서 다음 명령을 실행합니다.
`USER@SERVER`는 실제 SSH 접속 계정·주소로 바꾸세요.

```bash
ssh -L 4173:127.0.0.1:4173 USER@SERVER
```

그다음 개인 PC 브라우저에서 http://localhost:4173 을 엽니다.

## 제작 대상과 현재 상태

제작 대상은 경북대 패션디자인학과의 DDP 졸업 패션쇼에 방문하는 관객을 위한 모바일 초대장·팜플릿입니다.
현재 저장소에는 참고 사이트를 재현한 기존 화면과 별도 디자인 목업이 있으며, 화면의 행사명·일정·작품·이미지는 아직 실제 행사 확정 정보가 아닙니다.
행사 공식 명칭과 일정, DDP 내 상세 장소, 디자인 자료, 출품작 및 디자이너 정보, 좌석 조회 필요 여부를 확인한 뒤 반영합니다.

## 미팅 자료 보관

미팅 메모, 녹취, PDF, 전달받은 이미지 등은 프로젝트 내 `private/meetings/`에 넣습니다.
여러 차례 미팅을 구분하려면 `private/meetings/YYYY-MM-DD/`처럼 날짜별 하위 폴더를 사용합니다.
`private/`는 Git 추적 및 사이트 배포에서 제외되는 로컬 자료 폴더입니다.
현재 전달받은 회의록은 `meetings/2026_10_08_패션쇼 좌석 배정 및 NFC 안내.md`에 있으며, `meetings/`도 Git 추적 및 사이트 배포에서 제외합니다.
지정 좌석 엑셀 원본은 `private/rosters/`, 무대팀 보고서 등 참고 PDF는 `private/references/`에 보관합니다.

### Spectrum 구현 상태 (2026-10-09)

Figma MCP 연결과 파일 접근을 확인하고 `spectrum/`에 HTML·CSS·JavaScript로 구현했습니다.
`index.html`과 `design.css`는 Figma 레이어 구조·수치를 반영하며, `app.css`는 모바일 스크롤·반응형 배치·인터랙션 스타일을 관리합니다.
기존 루트 레퍼런스와 `mockup/`은 별도로 유지합니다. 새 모바일 구현은 `/spectrum/`에 공개 배포합니다.
구현 대상은 모바일 전용입니다. 모든 기기에서 최대 390px의 동일한 단일 화면을 사용하며 PC 전용 화면은 만들지 않습니다.
작은 휴대폰·가로 화면에서는 본문을 스크롤하고 하단 이동 버튼은 화면 안에 유지합니다.
Figma의 시간·통신·와이파이·배터리 표시는 기기 샘플 UI이므로 제거했습니다. 실제 노치 영역은 `safe-area-inset-top`으로 처리합니다.

- 메인 초대장, 쇼 소개, 오시는 길, 전시 소개, 디자이너(39명/6개 스테이지), 타임라인, 좌석배치도, 유의사항
- 티켓을 열면 전화번호 입력창에 포커스하고 `010 · 0000 · 0001`처럼 자동으로 구분합니다. 숫자 중간 편집·구분자 삭제·붙여넣기를 지원합니다.
- 조회가 성공하면 티켓 팝업 안에서 이름·좌석 위치·배치도만 담긴 간단한 결과 화면을 표시합니다. 개발 버전에서는 첫 화면에서 조회에 성공하면 배경이 쇼 소개로 이동하여 결과를 닫은 뒤 소개를 이어 볼 수 있습니다. 다른 안내 화면에서 재조회하면 해당 화면을 유지하며, 조회 실패·입력 취소 시에는 이동하지 않습니다. 추가 확인 버튼은 없으며 VIP는 이름과 V1/V2 선착순 구역을 표시합니다.
- 같은 조회 결과를 06 좌석배치도에도 유지합니다. 다른 번호 조회에 성공하면 두 화면의 이름·위치·강조 표시가 함께 바뀌며, 입력 취소나 조회 실패 시에는 직전 결과를 유지합니다. 새로고침하면 초기화됩니다.
- 개발 버전의 좌석 결과 팝업 뒤는 불투명한 검은 배경으로 가립니다. 첫 화면에서 조회한 관객은 결과를 닫을 때 쇼 소개 화면을 보게 됩니다.
- 전화번호 조회 후 지정 좌석 칸만 밝힙니다. 구역 전체 강조와 구역 위의 번호 표시는 제거했습니다. 동반 좌석은 각 해당 칸을 함께 밝힙니다.
- 번호와 위치는 `09.30 무대팀 진행상황 보고.pdf` 17페이지를 기준으로 연결했습니다. A–F 각 30석, 총 180석입니다.
- A–C는 위에서부터 `f/g 1–5` → `a–e 3/4` → `a–e 1/2`, D–F는 `a–e 1/2` → `a–e 3/4` → `f/g 1–5` 순입니다. 각 줄은 화면 왼쪽부터 오른쪽 순서입니다.
- 좌석 키는 `A-a-1` 형식입니다. 모호한 `A01` 같은 임의 일련번호를 의자에 대응시키지 않습니다.
- VIP는 V1·V2를 합친 하나의 선착순 구역입니다. 개발 버전에서는 명단이 `V1` 또는 `V2`로 적혀 있어도 항상 두 구역을 함께 표시합니다. 원본의 `vip` 표기가 있으면 임시 지정석 번호보다 우선합니다.
- 네이버 지도는 DDP 패션몰 검색으로 연결합니다.
- Figma 이미지·SVG 70개를 로컬에 저장했습니다. 임시 Figma URL에 의존하지 않습니다.
- 조회 결과와 전화번호는 브라우저 저장소에 기록하지 않으며 새로고침하면 초기화됩니다. 입장 처리나 좌석 예약 기능은 없습니다.

현재 `spectrum/seats.csv`는 가상 명단입니다. 개발 버전의 클라이언트 확인용 번호는 `01000000001`(A-a-1), `01000000002`(VIP V1·V2 통합 선착순)입니다. `01000000004`·`01000000005`도 같은 통합 VIP로 표시합니다.
`01000000003`의 B-a-1·B-a-2·B-a-3은 한 번호의 복수 좌석 처리를 검증하는 개발용 가상 사례이며, 실제 행사의 동반 좌석 정책을 뜻하지 않습니다.
사용자가 허용한 Python 기본 기능으로 `private/rosters/지정좌석.xlsx`를 읽어 실제 명단을 로컬 미리보기에 연결했습니다.
현재 일반 좌석 152건, VIP 16건, 총 168개 전화번호입니다. 원본 엑셀에서 전화번호가 비어 있는 50행은 제외했습니다.
별도 등록한 VIP는 `private/rosters/vip-guests.json`에 보관하고, 엑셀을 다시 변환해도 우선 반영합니다. 두 선착순 구역을 이용하며 개별 의자는 지정하지 않습니다.
`C_f-1` 같은 구분자 차이는 읽을 때만 정규화합니다. 원본 엑셀은 변경하지 않습니다.
사용자 요청에 따라 조회 API를 제거하고 브라우저가 정적 CSV를 직접 조회하도록 변경했습니다.
변환 중간 파일은 `private/rosters/lookup.json`에 두고, `build.py --roster`를 사용하면 전화번호 해시·이름·좌석·VIP 구분만 `dist/spectrum/seats.csv`에 내보냅니다.
이름·좌석·해시는 다운로드 가능한 공개 데이터입니다. 전화번호 원문을 빼도 암호화나 접근 제한이 되지는 않습니다.
엑셀·PDF 원본과 추가 VIP 원본은 계속 Git 및 배포 대상에서 제외합니다. `--include-demo`를 지정하면 테스트 번호도 함께 포함합니다.
무대팀 보고서 `09.30 무대팀 진행상황 보고.pdf`는 다운로드 폴더에서 찾아 `private/references/`에 복사했습니다. 원본은 그대로 유지합니다.
기존과 마찬가지로 정적 CSV는 다운로드할 수 있으므로, 해시 처리만으로 명단이 비공개가 되지는 않습니다.

화면 문구는 Figma 원문을 유지합니다. 회의록이나 보고서와 차이가 있어도 사용자 확인 없이 추가·수정하지 않습니다.
메인의 14:00–18:00, 쇼 소개의 운영 시간 16:00–16:30도 Figma 원문으로 복원했습니다.
회의록에서 가져와 추가했던 V1·V2 선착순 및 교수석 제외 안내는 화면과 조회 결과에서 삭제했습니다.

## 실제 명단 교체

1. `private/` 폴더에 원본 명단을 둡니다. 이 폴더는 Git 제외 대상이며 배포에 포함되지 않습니다.
2. UTF-8 CSV의 열 이름은 `phone,seat,name,vip`로 작성합니다. `name`과 `vip`는 생략 가능하고, VIP는 `vip`로 표기합니다.
3. 전화번호 열은 엑셀에서 텍스트로 지정해 앞의 0이 없어지지 않게 합니다.
4. 한 전화번호로 여러 좌석을 연결하려면 행을 추가합니다. 같은 지정 좌석의 중복 배정은 오류로 처리됩니다.
5. `seat`가 정확히 `V1` 또는 `V2`이면 선착순 구역으로 처리하며 여러 관객에게 같은 구역을 배정할 수 있습니다. `V01` 같은 기존 지정 좌석 번호와는 다릅니다.
6. `seat`가 비어 있는 행은 건너뜁니다. 유효한 배정이 하나도 없거나 입력 오류가 있으면 기존 출력 명단을 덮어쓰지 않습니다.

변환 결과의 `seat_type`은 지정 좌석이면 `assigned`, 선착순 구역이면 `zone`입니다.
구역 정원·예약 가능 여부를 판정하거나 좌석을 새로 예약하는 기능은 아닙니다. 현재 레퍼런스·목업은 이 구분을 화면에 반영하지 않으며, 새 행사 화면에서 연결할 예정입니다.

```bash
python3 scripts/prepare_seats.py private/guests.csv
python3 scripts/build.py
```

공개되는 seats.csv에는 전화번호 원문 대신 SHA-256 해시가 들어갑니다.
이것은 접근 제한이나 암호화된 비공개 명단이 아닙니다. 좌석·이름·해시가 브라우저에 전달됩니다.
이름이 불필요하면 name을 비워 두세요. 명단 비공개가 필요하면 서버 조회 방식으로 변경해야 합니다.
현재 원본과 같은 서비스 워커가 명단도 캐시하므로, 배포를 종료해도 기존 방문자 기기의 캐시까지 원격 삭제되지는 않습니다.

## 배포

### GitHub Pages

공개 미리보기 주소: https://gxonu.github.io/fashion-show-invitation/

`main`은 원본 코드, `gh-pages`는 공개 웹사이트 파일만 관리합니다.
GitHub Pages의 배포 소스는 `gh-pages` 브랜치의 루트(`/`)입니다.
소스 수정 후 main에 커밋·푸시하고 다음 명령으로 사이트를 갱신합니다.

```bash
# 가상 명단으로 배포
python3 scripts/deploy_pages.py
# 확정 명단을 정적 조회 파일로 포함해 배포 (이름·좌석·해시가 공개됨)
python3 scripts/deploy_pages.py --roster private/rosters/lookup.json
```

현재 구성은 main 푸시만으로 사이트가 자동 갱신되지 않습니다. 위 배포 명령이 필요합니다.
이 명령은 기존 Git 인증을 사용합니다. PAT를 코드·README·명령 인수에 넣지 마세요.
GitHub Pages 배포가 완료되기까지 잠시 시간이 걸릴 수 있습니다.
별도 서버 운영이나 도메인 구매 없이 휴대폰과 PC에서 공개 주소로 접속할 수 있습니다.
원격 개발 서버를 종료해도 GitHub Pages는 계속 호스팅합니다.

### Netlify로 옮기는 경우

수동 배포: `python3 scripts/build.py` 실행 후 **dist 폴더만** Netlify에 업로드합니다.
Git 연동: 이 폴더를 프로젝트의 기준 폴더로 설정하면 netlify.toml의 명령으로 빌드합니다.
Netlify에서 사이트를 공개한 뒤 제공하는 `이름.netlify.app` 주소로 공유하면 됩니다.
별도 도메인은 필수가 아닙니다.
프로젝트 전체 대신 dist만 업로드합니다. 실제 명단을 포함하려면 `python3 scripts/build.py --roster private/rosters/lookup.json`으로 먼저 빌드합니다. 이 경우 조회용 이름·좌석·해시는 공개됩니다. Git 연동의 기본 빌드는 가상 명단을 사용합니다.

원본 서비스 워커 캐시를 유지합니다. 배포 내용을 변경할 때 service-worker.js의 CACHE_NAME을 올리고
index.html의 styles.css/script.js 버전도 갱신하세요. 로컬 개발 중 이전 화면이 보이면
브라우저 개발자 도구에서 서비스 워커 등록 해제 및 사이트 데이터 삭제 후 새로고침합니다.

공개 전에는 제공받은 새 디자인·행사 콘텐츠·실제 명단으로 교체하고 행사 시작 시각을 확인하세요.
